# Applied dominants in the chord dropdown: decisions

Stream: `feature/applied-dominant-suggestions`. Under a chromatic melody note the dropdown's main list offered only diatonic chords, each with the note as a tension (a G# in G major got ii, V and iii), while E7, the chord that explains it, sat under "Something else…".

- **2026-10-07 — A chromatic melody note brings up to two applied dominants into the main list.** The pool is V7/x for x in ii, iii, IV, V and vi in major, and V7/V in minor. A chord qualifies only when the note is its 3rd, 5th or 7th; a V7/x root is always diatonic, so the root never qualifies. The qualifiers are ranked by the existing `fit` score, and the top two join the six likely chords, which are then sorted by fit as before. All of this lives in `src/chords/options.js`; `src/theory` is unchanged. _Rejected:_ promoting the whole extended list for chromatic notes (borrowed and passing chords would crowd the list); more than two (the main list would be mostly chromatic for one note).
- **2026-10-07 — Ties go to the chord where the note is the 3rd, then the 7th, then the 5th.** A raised note is most often the leading tone of the chord being tonicized, which is the 3rd of its V7/x (G# in E7 → Am), and a lowered note is most often its 7th (F in G7 → C). Without this, a lone C# in G major gave F#7 (V7/iii, C# as the 5th) the same score as A7 (V7/V, C# as the 3rd), and the list order picked iii. _Rejected:_ looking ahead to the next melody note to find the target (fit already reads the notes in the chord's span; a second, different look-ahead would be hard to explain in a why label).
- **2026-10-07 — Minor's raised 6th and 7th are not chromatic.** They are part of melodic and harmonic minor, and the minor likely list already has V for the leading tone. So Greensleeves' C# and D# in E minor add nothing, and its main lists are unchanged. In minor only #4 (A# in E minor, the 3rd of F#7) brings up an applied chord. _Rejected:_ minor's whole extended applied set (V7/iv, V7/VI): with the raised 6th and 7th excluded, they explain no other chromatic note better than the plain list does.
- **2026-10-07 — Sevenths only; labels come from the existing theory functions (gate on PR 45).** Each option's numeral is `numeralOf`'s, its Nashville and letter labels come from `chordView` as before, and its color from `functionOf`. `numeralOf` names only dominant sevenths as applied (see `a-theory.md`: a major triad off the scale is just as often borrowed), so E7 in G reads "V7/ii" and is colored dominant. The E triad would read "VI" in grey "other" right after a red V7/ii, two opposite stories about the same root, so the triads stay out of the main list. The brief asked for V/x too; that would need new naming in `numeralOf`, which this stream doesn't own. _Rejected:_ V/x triads in the pool (first draft of this PR; dropped at the gate).
- **2026-10-07 — Applied options get no number key.** Each reads back as V7/x, which `degreeOf` already maps to null. The extended list now dedupes against the main list as shown, so an applied chord never appears twice.
- **2026-10-07 — Diatonic notes are pinned by a snapshot.** `tests/chords/diatonic-main-lists.json` holds every note's main list (chord, numeral and fit) for Ode to Joy, St. James Infirmary, Amazing Grace and Greensleeves, generated from `main`'s `options.js` before this change, and the test asserts the new code reproduces it exactly. The test says how to regenerate it.
