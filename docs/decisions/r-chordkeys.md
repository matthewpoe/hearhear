# Stream R: chord row (harmonize from the keyboard)

Format: **date — decision.** Why. _Rejected:_ alternatives.

- **2026-10-07 — The A–J row plays chords by default (`ui.bottomRow`, "chords" or "notes").** Matthew: playing the root of a chord from the keys is one of the easiest ways to harmonize, especially while freestyling a melody. A visible "Bottom row: Chords / Notes" switch in the keyboard dock sets it, and "notes" restores the fixed-row behavior exactly (two octaves under the number row, Shift and Alt working). **Deviates from the PRD and DECISIONS ("fixed number rows"),** where A–J always plays single notes two octaves down. Every column still means one degree: 1 over Q over A, and A is the home chord. _Rejected:_ a new row (no free row lines up with the number row); keeping notes as the default.
- **2026-10-07 — Major plays I ii iii IV V vi vii°; minor plays i ii° III iv V VI VII.** Minor follows the theory core's convention for the dropdown's likely suspects (`COMMON.minor` in `src/theory/candidates.js` lists V, not v): natural minor with the major V a cadence calls for, matching the PRD's raised seventh "at cadences". Degree 7 in minor is the subtonic VII, as natural minor has it. Functions come from `functionOf`, so the colors match the chips. _Rejected:_ v in minor (the dropdown never offers it); vii° in minor (the core offers only #vii°7, among the extended chords).
- **2026-10-07 — Shift and Alt do nothing on the chord row.** Shift+A plays the same chord as A, and the key is claimed (preventDefault) either way so Option doesn't type a symbol. The armed one-shot flat (`-`) is left for the next note. Chromatic and seventh chords stay in the dropdown's "Something else…". _Rejected:_ Shift for a seventh, Alt for the borrowed chord (more to learn than the row is for).
- **2026-10-07 — Live chords are voiced in root position under home** (degree 1 of the number row in the current octave window), with `voice(chord, null, { below: home })`, so the floor of C2 holds and every press of a key sounds the same. Zero look-ahead and no voice leading from the previous press: a live instrument should be predictable under the fingers. It can overlap the Q row, which is the octave under home. _Rejected:_ voice leading from the last chord played (the same key would sound different press to press, which fixed rows were chosen to avoid).
- **2026-10-07 — Assigning goes through the store only.** With a staff note selected (`ui.selectedNoteId`) and the key confirmed, a chord-row key calls `song.setChord(noteId, chord)` (one undoable action) and sounds the chord under the note, voiced with `voice(chord, null, { below: note.midi })`, with the note on top. Backspace or Delete with a note selected clears its chord (`setChord(noteId, null)`), only under the same conditions and only when there is a chord to clear, so it never swallows Backspace otherwise. While the key is hidden or tentative the row only plays; it never writes. Form fields own their keys, as for the number row. The chord dropdown's internals are untouched.
- **2026-10-07 — The chord dropdown owns `ui.selectedNoteId`.** Review found nothing wrote it, so the row could never assign. The dropdown sets it to the note it opens on and clears it on every close (Escape, outside click, tabbing out, choosing, the note vanishing), all of which go through its `close()`. So the selected note is the open dropdown's note: press a note, then A–J places chords on it while the list stays open, and the placed chord's display follows `song.chords`. The dropdown handles only Escape, the arrows, and 1–7, so letter keys reach the window handler with focus inside it. _Rejected:_ a separate staff selection (a second notion of "the current note" for the user to track).
- **2026-10-07 — A held chord lights from a store in `src/input`, not `ui.keyboardLights`.** The contract names two sources, "playback" and "hover", owned by playback and the chord dropdown; writing "hover" from the keyboard would let the dropdown clear our lights, or ours clear its. `NumberRow.js` exports `heldChord` (the chord-row chord held now, with its function), and the piano lights it in its function color whenever no writer owns `keyboardLights`. Held keys also sink as before. Hidden mode stays neutral, as for all chord lights. _Rejected:_ a new `source` value (a contract change).
- **2026-10-07 — The piano labels each chord-row key's chord on its root, two octaves under the number row** (where A–J's single notes sit), in place of the degree: "I", "1", or "C" by label style, with the computer key under it. Numerals plus letters shows the numeral, since "I · C" doesn't fit a key. Hidden mode shows nothing, as for every key label; the accessible name says "key A plays a chord". While the row plays chords, `keyBindings` leaves A–J out, so no key claims they play single notes. Labels follow the octave window. _Rejected:_ a separate chord legend strip (more height, against the compact dock).
- **2026-10-07 — The dock is compact: keys 5.5rem tall (were 8.5rem), a tighter header and padding,** about 145px at 1280 wide with the help line on the header row. Keys keep their 1.75rem minimum width for touch, and the switch buttons are 2rem tall. The switch is two buttons with `aria-pressed`, not radio inputs: the number row ignores keys while focus is in an `input`, so a radio would silence the keyboard after a click.
- **2026-10-07 — One help line while the row plays chords:** "Bottom row plays chords: A is the home chord (1), F is 4, G is 5." It's hidden on Notes, where the row behaves as the PRD describes.
- **2026-10-07 — Tests:** `tests/input/chordRow.test.js` covers degree to chord in major and minor, assign vs play under each key-label mode, the switch's effect on `keyBindings`, and the label positions; `tests/input/numberRow.test.js` covers held chords, assigning as one undoable action, no assignment while tentative or hidden, Backspace and Delete, and text fields. The existing number-row tests now set `bottomRow: "notes"`, since they test single notes on A–J.
