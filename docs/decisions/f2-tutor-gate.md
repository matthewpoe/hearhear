# Stream F2: tutor passphrase and chord-identity validation

Format: **date — decision.** Why. _Rejected:_ alternatives.

- **2026-10-07 — A `#code=` link's passphrase is kept in sessionStorage for that tab; a typed one stays in memory only.** The brief asks for this so a reviewer who opens the submission link can refresh without being asked. **Deviation from DECISIONS.md**, which says the browser keeps the code in memory only and "a reload asks again, unless a `#code=` fragment supplies it" (the fragment is gone after the first load, so in practice a reload would ask). sessionStorage is per tab and cleared when the tab closes; nothing goes to localStorage. Matthew should confirm. _Rejected:_ memory only for linked codes too (a refresh would lose the link's code); localStorage (survives the session, ruled out).
- **2026-10-07 — A rejected passphrase is forgotten, in memory and in sessionStorage.** Otherwise a wrong linked code would be resent on every refresh and count toward the wrong-code lockout. _Rejected:_ keeping it until the user types another.
- **2026-10-07 — `access_required` opens a prompt in place of the failure line; Unlock resends the same question.** The user doesn't retype anything, and the passphrase field takes focus with the prompt and the recorded-lessons line as its description, so a screen reader reads both. If a code was sent and turned away, the prompt adds "That one didn't match." _Rejected:_ a failure alert with a retry button (reads as an error, against the "warm prompt" requirement).
- **2026-10-07 — `access_locked` is retryable and has its own line** ("Too many wrong codes. Try again in a few minutes."). The lockout lifts by itself, so Try again works later. _Rejected:_ treating it as final like `over_budget`.
- **2026-10-07 — The passphrase field is `type="password"`.** It keeps the code off a shared or recorded screen (the demo video). _Rejected:_ a plain text field.
- **2026-10-07 — A bare 401 (no envelope) still maps to `network`.** Only our envelope says the tutor wants a passphrase; a bare 401 is from something in front of it. The existing test for this stays.
- **2026-10-07 — `chordFromLetter` and `sameChord` both live in `src/theory/letters.js`, exported on one line.** Comparing root pitch classes is theory, and theory stays in `src/theory/`; validate.js only asks whether two chords are the same. **Adds `sameChord` to the theory API beyond the brief's `chordFromLetter`**; contracts/README.md's export list needs both (requested, not edited). _Rejected:_ comparing `Note.chroma` from Tonal inside validate.js (theory outside the theory core).
- **2026-10-07 — `chordFromLetter` accepts exactly the brief's suffixes and single `#` or `b` roots.** Anything else (`Cmaj9`, `G/B`, `A##`) returns null and the suggestion is dropped and counted. The song schema can't hold those chords, so there is nothing to keep. The root keeps the tutor's spelling; validation stores the numeral's chord instead.
