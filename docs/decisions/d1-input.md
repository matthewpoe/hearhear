# Stream D1: piano and noodle mode (wave 1)

Format: **date — decision.** Why. _Rejected:_ alternatives.

- **2026-10-07 — Windows Alt is unverified; the `-` one-shot flat fallback ships, on every platform.** There is no Windows browser in this environment, so Alt+letter (Alt+D, Alt+F, Alt+E in Chrome, Edge, and Firefox) could not be tested. `NumberRow.js` sets `ONE_SHOT_FLAT_FALLBACK = true`: `-` (KeyboardEvent.code `Minus`) arms a flat for the next note, a second `-` or Escape disarms it, and the piano bar shows "♭ next note" while it is armed. Alt/Option still lowers, with preventDefault, as DECISIONS.md requires. Someone with Windows Chrome, Edge, and Firefox should check Alt+D, Alt+F, and Alt+E before deciding whether to keep the fallback. _Rejected:_ enabling it only on Windows (platform sniffing for a key that does no harm elsewhere); Alt with no fallback.
- **2026-10-07 — In hidden mode the piano hides the computer-key labels as well as the degrees.** On the provisional C, the number-row labels are 1–7 on the white keys from C, which read exactly as degree labels and would suggest that C is home. Accessible names drop to the pitch alone ("C4"). Keys still play, and chord tones still light, in a neutral color. _Rejected:_ showing computer keys in hidden mode (they give away a home that isn't the answer).
- **2026-10-07 — Tentative labels are italic at full contrast; the tentative opacity token applies only to chord outlines.** The smoke test runs axe in the default state, which is tentative, and key labels at `--tentative-opacity` would fail AA. Lit chord tones in tentative mode get an inset ring in the function color (yellow uses `--fn-subdominant-edge`) at `--tentative-opacity`, with no fill, as `tokens.css` describes. _Rejected:_ dimming the text.
- **2026-10-07 — Lit chord tones carry their Bauhaus shape** (circle, triangle, square, "?") as a small mark on the key, so the keyboard never relies on color alone. When a melody note is also a chord tone, the chord color wins in confirmed mode. In tentative mode both show, since the chord is an outline.
- **2026-10-07 — The arrows move the octave window one octave either way (`WINDOW_OCTAVE_LIMIT = 1`).** With the tonic near C4, ±1 keeps the home row inside the C2–C6 piano and samples. Arrows are ignored on auto-repeat and never scroll. The PRD's "with a note selected, the arrows move that note an octave" is note editing, which is wave 2, so in wave 1 the arrows always move the window. _Rejected:_ no limit (notes outside the sampled range).
- **2026-10-07 — One held-notes store (`src/input/liveNotes.js`) for both inputs.** The piano and the number row press and release through it, so a note sounds once and lights its key however it was played. Pressing a pitch that is already held does nothing. This is the seed of the PRD's single note-event stream; record mode in wave 2 will read from it. _Rejected:_ separate pressed state per input.
- **2026-10-07 — Number-row ownership rule: a handler that consumes a key calls preventDefault, and the number row skips `defaultPrevented` events.** The chord dropdown (D2) auditions by degree on the same keys while it is open; its element-level listener runs before the number row's window listener. Form fields (input, textarea, select, contenteditable) own all their keys, which goes slightly beyond the PRD's "text field" so that arrows in a select or slider never move the window. Cmd and Ctrl chords are left alone (undo, tab switching).
- **2026-10-07 — Held number-row keys remember their pitch.** A key releases the note it started even if Shift, the window, or the song's key changed while it was down. Leaving the window releases every held note, since no key-up will arrive.
- **2026-10-07 — Computer-key labels pick the simplest way to play each pitch:** plain keys first, then Shift, then Alt/Option (shown as ⌥ on Mac and "Alt" elsewhere). Degree labels come from `midiToDegree` without the window offset, so the dots describe the music, matching the staff's degree line, not where the window sits.
- **2026-10-07 — Piano keyboard access uses one tab stop (roving tabindex).** Left and Right arrows (and Home, End) move along the keys, and Space or Enter holds the focused key. A click with no pointer press behind it (screen-reader activation) plays a 400 ms note. _Rejected:_ 49 tab stops.
- **2026-10-07 — The piano shows the sample-loading boundary:** "Loading piano sound…", or "Piano sound didn't load" with a Retry button that calls `preload()`, read from `audioStatus`. The piano is the instrument, so its sound state belongs here. If D3's landing screen also shows it, integration should keep one.

## Wave-1 fixes

- **2026-10-07 — Rebased on `merge/a-theory`; the piano uses the shared `src/lib/FunctionMark.svelte`** and the local copy is gone.
- **2026-10-07 — Tentative chord tones use the per-key-surface tokens (D7).** Outline and mark draw in `--fn-*-on-white-key` on ivory keys and `--fn-*-on-black-key` on black keys, at full opacity; `--tentative-opacity` no longer touches keys. Confirmed tones keep the `--fn-*` fill with `--fn-*-ink` marks.
- **2026-10-07 — The piano reads `ui.keyboardLights.source` (D10)** and lights keys only while a writer (playback or hover) owns them, so a stale `chord` or `melody` left under `source: null` never shows. In hidden mode no function color or shape shows, as before.
- **2026-10-07 — The piano shows only "Couldn't load the piano sound" with Retry when audio has failed (D19).** The "Loading piano sound…" line is gone; the landing screen owns preload and the sound check.
- **2026-10-07 — Keys use `touch-action: pan-x`,** so a phone can scroll the piano to C4. A tap or hold still plays at once; a horizontal drag pans and fires `pointercancel`, which releases the note.
- **2026-10-07 — Mouse and touch presses capture the pointer** (`setPointerCapture`), and `pointerleave` no longer releases. Sliding onto a neighbouring key keeps the note, as on a real piano.
- **2026-10-07 — Space/Enter on a focused key remembers the key it pressed** and releases that one on key-up or when focus leaves the piano (moving with the arrows while holding), so no note is stranded.
- **2026-10-07 — Held notes are tracked per source** (`press(midi, source)`, `release(midi, source)`; sources are `key:<code>`, `pointer:<id>`, `focus`, `tap:<n>`). A note stops only when the last source lets go, so lifting a finger off a piano key never cuts off the same pitch held on the number row.
- **2026-10-07 — The octave window is clamped per key so every bound key lands on the C2–C6 piano** (`windowBounds` and `clampWindow` in `keyBindings.js`, computed with theory's `degreeToMidi`). A window is allowed only when every plain key of the three rows lands on the piano. Keystrokes that would still fall off it (Alt on the A row, Shift on the top keys) play nothing and get no label. This corrects the earlier entry: `WINDOW_OCTAVE_LIMIT = 1` did not keep the rows on the piano (A-row keys fell below C2 at window −1, top keys above C6 at +1). **Consequence, flagged for Matthew:** with `tonicMidi` at C4–B4, the three rows span 40 of the piano's 48 semitones, so every key has exactly one allowed window (home), and the arrows move nothing. For A, B♭, and B major (and B♭, B minor) no window fits every plain key; the window stays home and the top one or two keys are silent. Reopening the arrows needs a different rule (for example, clamp only the home row and silence what falls off) or a smaller piano span per row.
- **2026-10-07 — The ⌥/Alt label branch is gone.** Every lowered degree is also a plain or raised neighbour on the piano, so it never rendered; labels are plain or ⇧ only. Alt/Option and `-` still lower; teaching them belongs to the help text. This corrects the earlier entry on computer-key labels.
- **2026-10-07 — Readability:** one `ACCIDENTAL` table (glyph and spoken), one `MODIFIER_LABELS` table, `$state.raw` for the key refs, and the confirm reveal fades the chord fill at `--dur-reveal` once, on entering confirmed mode. Differs from the reviewer's proposal: a `data-mode` selector alone would slow every later chord change during playback, so a short-lived `revealing` class carries the slow fade only for the reveal itself.
- **2026-10-07 — Unit tests (D6):** `tests/input/keyBindings.test.js` (bindings in C major, nothing off the piano in any key or window, window bounds, labels) and `tests/input/numberRow.test.js` (rows and Shift, Alt, auto-repeat, form fields and Cmd/Ctrl and claimed keys, held keys remember their pitch, arrows clamp and never scroll, off-piano keys are silent, `-` arms for one note, blur releases all, per-source holds).
