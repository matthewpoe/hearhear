# Stream K: beginner callouts

Format: **date — decision.** Why. _Rejected:_ alternatives.

- **2026-10-07 — `content/callouts.json` keeps its Phase 0 wrapper, `{ "$comment", "callouts": [...] }`, with each entry `{ id, anchor, title?, text, needsKeyLabels? }`.** The brief's shape is the array; the wrapper was already in the file and carries the note that Matthew owns the wording, as `explainers.json` does. Order in the file is the tour's order. _Rejected:_ a bare array (loses the ownership note).
- **2026-10-07 — Added `needsKeyLabels` (deviation from the brief's data shape).** Two tips explain key-relative labels: "These number keys are notes. 1 is home." and "Blue circle means home; red square means tension." In a demo before the guess (`keyLabelMode` hidden) the piano shows no degrees and chords show no colors, and "1 is home" would contradict the key prompt's question. Those two tips are skipped while labels are hidden and appear after the reveal. No callout names or hints at a key, so tentative and confirmed modes need no other handling. _Rejected:_ showing them anyway (points at colors that aren't there); rewording them to avoid labels (they are the PRD's own examples).
- **2026-10-07 — Eight tips: landing, key prompt, number keys (piano), staff, chord audition, function shapes (both on `chords`), toolbar, tutor.** Uses the PRD's three example lines as titles, glosses every term (home, key, scale, octave, chord, melody, transpose), and follows the PRD voice. `toolbar` and `key-prompt` don't exist on the page yet; they are skipped until those elements mount. All copy is draft for Matthew to rewrite.
- **2026-10-07 — Next and Close both remember the tip as seen; Close also puts tips away for the rest of the visit.** Next moves to the following tip and focuses it (the viewer asked for it). Close (the × button or Escape) ends the tour for this page visit, and the next visit picks up at the first unseen tip. The Next button reads "Got it" on the last available tip. _Rejected:_ Close dismissing only the current tip (pressing Escape would just summon the next tip, which isn't what Escape means); Close turning the toggle off (would silently change a remembered setting).
- **2026-10-07 — Dismissals are remembered in localStorage alongside the on/off setting; turning tips back on starts the tour over.** "On by default for a first visit" only holds if a returning viewer isn't re-shown tips they've read. Turning the toggle on is the one obvious way to see them again. Both values are per-viewer conveniences, read and written in try/catch with a console warning, and blocked storage just means forgetting on reload. Keys: `hearhear.callouts.on`, `hearhear.callouts.dismissed`. _Rejected:_ in-memory dismissals only (every reload restarts the tour); a separate "restart tips" button (one more control).
- **2026-10-07 — The component renders the toggle where it's placed, and the tip in a `position: fixed` layer.** Position comes from the anchor's `getBoundingClientRect()`: below the anchor if it fits, else above, else just inside its top edge (the staff can be taller than the screen), clamped to the viewport. It re-places on window scroll (captured, so inner scrolling counts), resize, and page changes. Fixed rather than absolute so tips beside the sticky keyboard dock stay put. The placement math is pure (`placeCallout` in `tour.js`) and tested. _Rejected:_ absolute positioning in page coordinates (wrong beside the sticky piano); a pointer arrow (more geometry, little gain for a beginner tip that sits right next to its target).
- **2026-10-07 — A `MutationObserver` on `body` (coalesced to one look-up per animation frame) re-checks anchors.** The landing leaves once a song loads and other panels mount later, so the current tip must follow what's on the page. It observes child lists only, not attributes, so playhead class toggles don't trigger it. _Rejected:_ checking once at mount (misses `toolbar` and `key-prompt` when they arrive); polling.
- **2026-10-07 — Accessibility.** The tip never takes focus when it appears. A visually hidden `aria-live="polite"` region (always in the DOM, so the change is announced) reads "Tip: title text". The tip is an `<aside>` labelled by its title and sits in the tab order right after the toggle; the toggle is a button with `aria-pressed`, matching the theme toggle. Escape closes the tip when focus is inside it or nowhere (on `body`), and skips events another control already handled (`defaultPrevented`), so the chord dropdown's Escape doesn't also close tips. Closing from inside returns focus to the toggle. The tip fades in over `--dur-land`; under `prefers-reduced-motion` it just appears.
- **2026-10-07 — Theme tokens only:** `--surface`, `--ink`, `--ink-muted`, `--paper`, `--rule`, spacing, radius, and motion tokens; both themes come for free. The tip uses an ink border rather than a function color, because every color in the app means a harmonic function.
- **2026-10-07 — Tests in `tests/callouts/`** cover `nextCallout` (order, dismissed, missing anchor, hidden labels), `placeCallout` (below, above, inside, horizontal and vertical clamping, oversize), the memory module with a stand-in storage and a throwing one, and that the content has unique ids and the required fields. No UI tests, per the brief.
