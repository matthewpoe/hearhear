# Stream F: tutor panel (wave-1 slice)

Format: **date — decision.** Why. _Rejected:_ alternatives.

- **2026-10-07 — Three small modules behind the panel: `sse.js` (event framing), `client.js` (POST, stream reader, error codes), `validate.js` (suggestion re-validation), plus `failures.js` for the copy.** Each is plain JS with no Svelte, so the stream and validation logic can be exercised in Node. _Rejected:_ one `client.js` that also validates (mixes network and theory); `EventSource` (GET-only, per `tutor-sse.md`).
- **2026-10-07 — Suggestions are validated against the exact song the snapshot was built from, and stored with that song's `version`.** The panel captures `song.get()` at send time, builds the snapshot from it, and validates the reply against it, so the version written to the store is the version validated against by construction. The server's `snapshot_version` echo is not re-read. Staleness then falls out of `isStale(set, $song.version)`. _Rejected:_ validating against the song at reply time (an edit mid-stream would anchor suggestions to a song they weren't made for); trusting the server's echo (one more value to cross-check for no gain).
- **2026-10-07 — A suggestion lands on a note when its bar matches and its beat is within 0.001 of the note's onset.** The snapshot rounds beats to three places, so triplet onsets (e.g. 1.333) must still match. Anchored by note id, so D2 reads `noteId` and never re-resolves positions.
- **2026-10-07 — The stored `dropped` is the server's count plus the client's.** The user sees one honest number ("2 didn't check out and were left off"), not two.
- **2026-10-07 — Any suggestion with a missing or mistyped field, a numeral that doesn't parse, a letter that disagrees with `chordFromNumeral`, or a position with no note onset is dropped.** The chord stored is the one `chordFromNumeral` derives, never Claude's letter string (PRD: chord strings from Claude are parsed and re-serialized).
- **2026-10-07 — Every reply's suggestions event replaces the store, including a nudge with zero suggestions.** Follows the store's `replace` contract; one reply, one set, one snapshot version. _Rejected:_ merging sets across replies (mixed versions would make staleness ambiguous).
- **2026-10-07 — Hint level: "Ask" always sends a nudge; "Show me options" (comparison) and "Tell me" (answer) unlock after the first tutor reply and send whatever is in the text box (or no question).** "Start at a nudge and escalate only when asked" — escalation is a reaction to a nudge, so it's offered once there is one. The level is per request, not sticky: the next plain Ask is a nudge again. Each tutor turn shows its level. _Rejected:_ a sticky radio group (a user who once said "Tell me" would keep getting answers); escalation available before any nudge (skips the withholding the PRD asks for).
- **2026-10-07 — History sent is the last 12 turns of the session log; the log shown on screen keeps every turn.** The request schema caps history at 12; the user still sees the whole conversation. A student turn is logged only when there was question text; a tutor turn is logged only on a successful reply. Failed exchanges are not sent as history.
- **2026-10-07 — Enter sends, Shift+Enter adds a line.** Matches chat convention; IME composition is respected. The text box is a normal `<textarea>`, so D1's focus check turns note keys off while it has focus.
- **2026-10-07 — Failures: every code gets a plain line; Retry shows for everything except `over_budget`, `too_large`, and `invalid_request`.** Those three fail the same way on retry (the budget resets daily). `over_budget` shows exactly "The live tutor is out of budget for today; the recorded lessons still work." Message text that streamed before a mid-stream error stays on screen (`tutor-sse.md`). Retry resends the same question and level with a fresh snapshot. The copy is the client's, by code, not the server's `message`. _Rejected:_ showing the server's message (fine as text, but the client owns the voice); Retry on every failure (offers a button that can't work).
- **2026-10-07 — Loading reads "The tutor is listening to your song…" in a status region; the in-progress reply is `aria-busy` while it streams.** Screen readers aren't fed every delta. The ellipsis breathes, and stops under `prefers-reduced-motion`.
- **2026-10-07 — No key-relative labels in the panel.** The panel shows no numerals, degrees, or function colors itself (the chord row shows suggestions), so `keyLabelMode` has nothing to gate here. The tutor's own prose can name numerals; see the proposed addition about demos before the guess.
- **2026-10-07 — No tests added.** The brief limits JS tests to `tests/theory/`, which Stream A owns. `checkSuggestions` and the SSE client were checked by hand against every fixture through the fixture-mode server (nudge, comparison, answer, malformed, over-budget, and a 422).
