# Stream F: tutor panel (wave-1 slice)

> Superseded by the review-mode decision (Oct 7): see DECISIONS.md.

Format: **date — decision.** Why. _Rejected:_ alternatives.

- **2026-10-07 — Three small modules behind the panel: `sse.js` (event framing), `client.js` (POST, stream reader, error codes), `validate.js` (suggestion re-validation), plus `failures.js` for the copy.** Each is plain JS with no Svelte, so the stream and validation logic can be exercised in Node. _Rejected:_ one `client.js` that also validates (mixes network and theory); `EventSource` (GET-only, per `tutor-sse.md`).
- **2026-10-07 — Suggestions are validated against the exact song the snapshot was built from, and stored with that song's `version`.** The panel captures `song.get()` at send time, builds the snapshot from it, and validates the reply against it, so the version written to the store is the version validated against by construction. The server's `snapshot_version` echo is not re-read. Staleness then falls out of `isStale(set, $song.version)`. _Rejected:_ validating against the song at reply time (an edit mid-stream would anchor suggestions to a song they weren't made for); trusting the server's echo (one more value to cross-check for no gain).
- **2026-10-07 — A suggestion lands on a note when its bar matches and its beat is within 0.001 of the note's onset.** The snapshot rounds beats to three places, so triplet onsets (e.g. 1.333) must still match. Anchored by note id, so D2 reads `noteId` and never re-resolves positions.
- **2026-10-07 — The stored `dropped` is the server's count plus the client's.** The user sees one honest number ("2 didn't check out and were left off"), not two.
- **2026-10-07 — Any suggestion with a missing or mistyped field, a numeral that doesn't parse, a letter that disagrees with `chordFromNumeral`, or a position with no note onset is dropped.** The chord stored is the one `chordFromNumeral` derives, never Claude's letter string (PRD: chord strings from Claude are parsed and re-serialized).
- **2026-10-07 — Every reply's suggestions event replaces the store, including a nudge with zero suggestions.** Follows the store's `replace` contract; one reply, one set, one snapshot version. _Rejected:_ merging sets across replies (mixed versions would make staleness ambiguous).
- **2026-10-07 — Hint level: "Ask" always sends a nudge; "Show me options" (comparison) and "Tell me" (answer) unlock after the first tutor reply and send whatever is in the text box (or no question).** "Start at a nudge and escalate only when asked" — escalation is a reaction to a nudge, so it's offered once there is one. The level is per request, not sticky: the next plain Ask is a nudge again. Each tutor turn shows its level. _Rejected:_ a sticky radio group (a user who once said "Tell me" would keep getting answers); escalation available before any nudge (skips the withholding the PRD asks for). _Superseded Oct 7 by Matthew's correction: one "Review my chords" action and a question box, no hint levels (DECISIONS.md)._
- **2026-10-07 — History sent is the last 12 turns of the session log; the log shown on screen keeps every turn.** The request schema caps history at 12; the user still sees the whole conversation. A student turn is logged only when there was question text; a tutor turn is logged only on a successful reply. Failed exchanges are not sent as history.
- **2026-10-07 — Enter sends, Shift+Enter adds a line.** Matches chat convention; IME composition is respected. The text box is a normal `<textarea>`, so D1's focus check turns note keys off while it has focus.
- **2026-10-07 — Failures: every code gets a plain line; Retry shows for everything except `over_budget`, `too_large`, and `invalid_request`.** Those three fail the same way on retry (the budget resets daily). `over_budget` shows exactly "The live tutor is out of budget for today; the recorded lessons still work." Message text that streamed before a mid-stream error stays on screen (`tutor-sse.md`). Retry resends the same question and level with a fresh snapshot. The copy is the client's, by code, not the server's `message`. _Rejected:_ showing the server's message (fine as text, but the client owns the voice); Retry on every failure (offers a button that can't work).
- **2026-10-07 — Loading reads "The tutor is listening to your song…" in a status region; the in-progress reply is `aria-busy` while it streams.** Screen readers aren't fed every delta. The ellipsis breathes, and stops under `prefers-reduced-motion`.
- **2026-10-07 — No key-relative labels in the panel.** The panel shows no numerals, degrees, or function colors itself (the chord row shows suggestions), so `keyLabelMode` has nothing to gate in the panel's own markup. The tutor's prose is gated by the server instead: see D5 and the wave-1 fixes below.
- **2026-10-07 — Tests for the pure modules (corrected in the wave-1 fixes).** The original entry said "No tests added" because "the brief limits JS tests to `tests/theory/`". That was wrong: `tests/store/` already existed, `package.json` runs `tests/**/*.test.js`, and D6 now allows unit tests for pure non-UI modules explicitly. `tests/tutor/` covers `sse.js`, `validate.js`, and `client.js`'s error mapping; the panel itself has no UI tests.

## Wave-1 fixes (2026-10-07)

> Superseded by the review-mode decision (Oct 7): see DECISIONS.md.

Matthew's triage of the Fable review, applied.

- **D5: the snapshot says when the key is hidden.** The panel calls `toTutorSnapshot(song, { labelStyle, keyHidden })` with `keyHidden = keyLabelMode(song, ui) === "hidden"`, so before the guess the server keeps the key out of the tutor's prose and withholds suggestions. This replaces the dangling "proposed addition about demos before the guess" (finding 9), which pointed at nothing. Stream E adds `key_hidden` to `snapshot.js` in parallel; on this branch `toTutorSnapshot` still ignores the extra property, so it takes effect when E's change lands.
- **D6 / finding 3: unit tests.** `tests/tutor/validate.test.js` (every fixture against its song, string bar and beat, off-beat and past-the-end positions, numeral and letter disagreeing, unparseable numeral, bad confidence, missing reason, null and non-object entries, a pickup note in bar 0, a triplet onset within rounding, and the dropped count when good and bad mix). `tests/tutor/sse.test.js` (every chunk size from 1 to 7 over LF, CRLF, and CR streams; multi-line data; comments; the default event). `tests/tutor/client.test.js` (the error mapping below and non-object event data), with `fetch` stubbed by real `Response` objects.
- **SSE: a CRLF split across chunks is no longer two line ends.** Found by the new tests, beyond the review: `push("data: a\r")` then `push("\ndata: b\r\n\r\n")` normalized each chunk separately, so the split pair became a blank line and ended the event early. The parser now holds a chunk-final `\r` until the next chunk, and `end()`, called by the client when the body closes, settles it.
- **Error mapping (finding 4).** The body's `{ error: { code } }` envelope still comes first. Without one (an edge proxy's HTML page, slowapi's default `{"error": "Rate limit exceeded…"}` string), the status decides: 413 `too_large`, 422 `invalid_request`, 429 `rate_limited`, any 5xx `network`. A 503 is `over_budget` only when the envelope says so. Other statuses stay `protocol`. The `network` copy now reads "Couldn't reach the tutor. Check your connection, or try again in a minute.", since a 5xx isn't the user's connection.
- **Non-object event data is `protocol` (finding 7).** `data: null`, a number, a string, or an array now fails as a garbled reply instead of throwing inside the reader loop and being reported as a cut-off connection.
- **A question typed during a reply is kept (finding 1).** `ask()` returns before clearing the text box while a reply streams; the draft stays for the next send.
- **The status region stays in the tree and always says the reply arrived (finding 2).** The `:empty { display: none }` rule is gone. An empty or completion-only region is visually hidden with a clip, not removed, so it's in the accessibility tree before its content changes. When a reply lands it reads "The tutor replied." (screen-reader only), followed by any visible suggestion and dropped counts. Deltas still never reach it. _Slightly different from the proposal:_ the completion line is hidden visually rather than shown, because sighted users can already see the reply arrive and a visible "The tutor replied." under it is noise.
- **Loading a different song starts a new conversation (finding 5).** When `$song.id` changes, the panel aborts any reply in flight, clears the log (so no history from the old song is sent), resets the failure state, and relocks escalation until the first nudge about the new song. Suggestions are cleared too, in the same step: both demo songs number their notes from n1, so a stale suggestion from one song could otherwise sit on the other song's note with the same id. (Corrected after the re-review: the first version of this entry relied on version-based staleness alone.) _Beyond the proposal:_ each exchange now checks its own `AbortController`, not the shared one, so an aborted old exchange can't be misread as a live one after a new send starts, and a reply that resolves just after an abort is discarded.
- **Hint level checked with `Object.hasOwn` (finding 6).** `"constructor"` and other inherited names no longer pass as a level.
- **Focus stays in the panel (finding 8).** `ask()` and `retry()` move focus to the text box, since the Ask and escalation buttons disable on press and Try again unmounts. Typing is the likely next action, and D1's focus check already turns note keys off there.
- **Checked in the browser** against the fixture-mode server on spare ports (8011 and 5291, not 8000): the status region is in the tree while empty, focus lands on the text box after Ask, a draft typed and Entered during a reply is kept, the region reads "The tutor replied." after a nudge, and loading another song mid-stream aborts the reply and clears the log and escalation.
