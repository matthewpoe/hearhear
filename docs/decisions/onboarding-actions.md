# Onboarding: every tip and tour step waits for one action

Format: **date — decision.** Why. _Rejected:_ alternatives.

Matthew: the onboarding "needs to be way more actionable and way more concise ... every callout that appears [should] have a tangible action that the user must take to advance to the next step." Builds on `docs/decisions/k-callouts.md` and `t-tour.md`, and the tour entry in DECISIONS.md (PR 32).

- **2026-10-07 — No Next and no Got it, in the tips or the tour.** A tip is done only when its `doneWhen` fact holds (the existing `actedOn`), and a tour step only when its `done` condition holds. `noNext` is gone because every tip is now that way. `tests/onboarding/actions.test.js` checks that every tip has a `doneWhen` the tour can observe, and that no tip's `when` already requires it. It checks that every step has a `done`, and that neither component's markup has a Next, Got it or Back button. _Rejected:_ keeping Next as a secondary "skip" (it is the advance Matthew asked to remove).
- **2026-10-07 — One quiet escape each: "Turn tips off" in the tip, "Leave tour" in the strip.** "Turn tips off" replaces the ×. It turns tips off as the masthead toggle does, and it does not mark the tip done, so turning tips back on shows the same tip. Escape now folds the tip into the "Tip" chip instead of closing the tour for the visit. It doesn't finish the tip either. _Rejected:_ the × closing for the visit while marking the tip seen (a way forward without the action); Escape turning tips off (a stray Escape would change a remembered setting).
- **2026-10-07 — New facts, wired from real state.** `notePlaying` (a single note held, from `heldNotes` with no chord-row chord) and `chordKeyHeld` (`heldChord` from the A–J row) come from the input stores. `chordRow` comes from `ui.bottomRow`. Like `playing`, these are momentary, so `actedOn` counts them only once the tip's moment has come. Page-observed facts live in content as `pageFacts`, a map of names to selectors: `finderOpen` (moved from code), `toolsOpen` (`#toolbar details[open]`) and `tutorAsked` (a student turn, or the passphrase prompt in live mode). The tips re-check on a short list of attribute changes (`WATCHED_ATTRIBUTES`), but not on class changes, which the playhead toggles on every note. _Rejected:_ a fact per feature in code (each new tip would need a code change); sticky "ever played" facts (pressing keys before choosing a key would skip the number-keys tip).
- **2026-10-07 — The seam for "Record a tune" is content only.** A new tip names a `pageFacts` selector for what recording shows on the page, such as a pressed record button, and a tip with that `doneWhen`. The unit test checks that every page fact is in the walk-through's fact list, so a new fact is covered there too. _Rejected:_ adding the record tip now (it belongs to that stream).
- **2026-10-07 — Explanation-only tips became actions or were cut.** "Your first job: find home" was cut: the key question already offers both paths, and its gloss of home moved into "Find home by ear" ("Press Help me find it..."). There is no tip inside the open finder, which says "Which one sounds like home?" itself. "Blue circle means home" became "Chords by color" ("Press A to J..."): the chord row lights each chord in its function color. It is skipped while the row plays notes. Placing a chord replays the phrase, so a "Press Play" action there would finish the tip before it showed. "1 is home" waits for a note on the number row. "Same tune, any key" waits for "Change key or transpose" to open, and the tutor tip waits for a question. _Rejected:_ a tip inside the finder (repeats its own text); "Press Play" for the shapes tip.
- **2026-10-07 — A tip whose subject is scrolled away waits behind the chip.** Opening "Change key or transpose" at 1280x800 pushes the tutor below the fold, and with Next gone the tutor tip would wait out of sight. When the next due tip's subject is on the page but not in view, the "Tip" chip shows ("Show the tip: Ask the tutor"), and pressing it scrolls the subject into view. `scrollForTip`, which only Next used, is removed. _Rejected:_ scrolling to the tip on its own (moves the page under someone who just acted, as in Stream T).
- **2026-10-07 — The tour strip has no Back, Next, Fold or More.** It holds the step's line, its one button and "Leave tour". On the last step, once it is done, "Finish" takes the place of "Leave tour". The `text` field (More) is cut. The placeholder status stays on the Draft badge's tooltip and in visually hidden text. A step whose condition already holds when the tour reaches it is skipped, which matches `actedOn` for tips. So resuming or restarting lands on the first step not yet done. _Rejected:_ keeping Back (going back to a done step would strand the viewer with no Next); keeping Fold (the strip is one line in the dock and covers nothing).
- **2026-10-07 — The tour's chord steps open the note's chords instead of auditioning for the viewer.** "Hear vi under the last note" played a chord but didn't advance, a second action beside the step's real one. Every chord step's button is now "Show me the note", which opens that note's chords, and placing the chord is the one action. Load, Play, the ear finder and "Ask the tutor" keep their buttons, which do the step's action. "Ask the tutor" is the only passphrase-free way to finish the last step in live mode. _Rejected:_ removing every strip button (a non-reader can't find "bar 4, beat 3" unaided).
- **2026-10-07 — `played` resets only when the song changes.** It was reset on every song edit (the effect read the whole song store), which didn't matter while done steps waited for Next. Now that they are skipped, it would have sent a restart back to "Hear it".
- **2026-10-07 — Copy is a revised draft; Matthew owns it.** Each tip and step leads with an imperative, has at most one clause of why, and has a 2–4 word title. The `$comment` in both files says so. Matthew reviewed the proposal and approved it with one edit: "Find home by ear" reads "Press Help me find it to hear the song's key, or which note the tune comes home to." Button names stay unquoted, as in the other tips.
- **2026-10-07 — The `toolbar` and `key-finder` anchors will be remapped in a follow-up** once the workspace redesign moves "Change key or transpose" into the key box. Only content changes: the anchors and the `toolsOpen` selector.
- **2026-10-07 — Verified in a browser at 1440x900 and 1280x800,** as a novice (Play, Help me find it, pick by ear) and as a musician (chooses D straight away), for both the tips and the tour, with a throwaway Playwright script against fixture mode. Every step completed by doing what it says. No tip covered the song list, the key question's controls, Play, the masthead toggles, the staff's notes, "Change key or transpose" or the tutor, and no dock tip overlapped the dock. There were no console errors. The only stall was the tutor tip at 1280 (above); the chip fixes it.
