# Stream K: key question feedback a first-timer can trust

Two first-time walkthroughs (a musician and a non-musician) found that any key guess was confirmed as fact ("Home is C major." for Ode to Joy). These are the decisions made fixing it.

- **2026-10-07 — A guess reads "You chose D major as home.", never "Home is …".** A guess is a hunch the user can change; "Home is" read as the app's verdict. _Rejected:_ keeping "Home is" and adding feedback beside it (the two would contradict on a mismatch).

- **2026-10-07 — Demo tunes answer a guess; other tunes stay neutral.** **Amends decision D14** ("the same next-step copy after any guess, right or wrong"). Both walkthroughs showed that colors alone carry no signal to a first-timer: they moved on with a wrong home. On a demo, a match says "That's the home most ears hear in this tune." with the usual next step; a mismatch says "Most ears hear home somewhere else in this tune. Listen to the last note over your home chord: does it settle, or hang?" with "Check it by ear" (opens the finder) and "Keep my choice". It never says "wrong" and never names the home, so the ear still does the finding. Non-demo tunes have no known key and say only "You chose X as home." _Rejected:_ naming the right key (does the ear work for the user); a silent mismatch (the blocker); a "Try again" button (a quiz, not an invitation).

- **2026-10-07 — "Keep my choice" stops the invitation for that tune for the page session.** A tune id goes into a small in-memory set (`src/finding/keptChoices.js`), which outlives the key prompt (it remounts per tune and when hidden). Later guesses on that tune that most ears don't share read neutrally; a match is still confirmed. _Rejected:_ remembering it in localStorage (a reload is a fair point to ask again); remembering per guess (would nag on the next wrong guess).

- **2026-10-07 — The right home note in the other mode gets its own line** ("You're close: most ears hear this same home note, but hear the tune a little differently. Try it bright and dark…"). Telling someone who chose D minor for a D major tune that "most ears hear home somewhere else" would be untrue. It hints at the mode without naming the key. _Rejected:_ using the general mismatch line for it.

- **2026-10-07 — The known key is the content file's key, followed through transposes.** `knownHome` measures how far the tune moved from a note both versions share by id (ids survive transposing) and shifts the content file's tonic by that much, so a demo transposed to C still knows its home. It returns null for any other tune. _Rejected:_ comparing with the content file's key as is (a transposed demo would call every right guess a mismatch); adding a "true key" field to the song or the ui store (a contract change, not needed).

- **2026-10-07 — The copy lives in `content/explainers.json` under `keyGuess`,** as Matthew's wording to edit, with `{key}` standing in for the guess. Views and the live region read the same strings.

- **2026-10-07 — The finder lineup never names or marks the current guess.** Before, the chord matching the guess was named and pressed, which turned the test into confirmation. Now every chord is unnamed until the user picks one; then the set's names are revealed and a line compares the pick with the earlier choice: "Same as your choice.", "Different from your earlier choice; your pick is now home.", or, with no earlier choice, "Your pick is now home." Picking the home already chosen still confirms ("Home is still D major.") rather than taking it back. _Rejected:_ revealing only the picked chord's name (the other two are what the user just compared).

- **2026-10-07 — The finder stays open after any pick,** including picking the home already chosen. Before, that pick closed the finder and returned focus; now the reveal and the comparison are the point of the pick, so they stay on screen. Close and Escape still close it. This changes the golden-path e2e test (see the stream's known gaps).

- **2026-10-07 — On a demo, the finder's first three always include the known home, and a set holding it never leads with its dominant.** If the known home ranks below third it takes third place, and the rest keep their order, so every key still appears once across "Try three more". The set is shuffled by the song id as before; then, if the dominant (any key on the fifth above home) is first, it swaps with a chord that isn't the home when there is one, so the fix doesn't simply put home first. For Ode to Joy the lineup is now F# minor, D major, A major (was A major first, the chord the novice took for home); for St. James, E major, B major, E minor. _Rejected:_ putting the known home in a fixed position (learnable); dropping the dominant from the set (it's a real, instructive contender).

- **2026-10-07 — "Help me find it" and "Check it by ear" scroll the finder into view** (`block: "nearest"`, smooth unless the user prefers reduced motion) and focus its heading with `preventScroll`, so the focus doesn't jump first. Asking again while it's open scrolls and focuses again rather than doing nothing. The page's `scroll-padding-bottom` keeps it clear of the docked keyboard.

- **2026-10-07 — The orphaned "Not now" after a guess becomes "Hide this card".** Before a guess (free play) "Not now" still puts the question off. After a guess the same button hides the card, and the landing region offers "Change the key" to bring it back. _Rejected:_ removing it (nothing else collapses the card once a guess is made).

- **2026-10-07 — No mode shows as chosen until the user picks one or a home.** "Bright (major)" was pre-selected, so users couldn't tell whether they had chosen it. A home chip clicked with no mode chosen commits major, then shows Bright as chosen with the line "Major unless you pick Dark." The one-click commit and un-commit and the un-click keeping the current tonic are unchanged.

- **2026-10-07 — After "Keep my choice", focus moves to the "Check it by ear" button that remains,** since the clicked button disappears.
