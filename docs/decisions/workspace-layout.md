# Workspace layout decisions

Stream: `feature/workspace-layout`, from Matthew's feedback on Oct 7, 2026 and the coordinator's steers that followed.

- **The tool row holds only Play, its scope, the label style, Undo/Redo, and Print.** Settings moved to their steps: Drone on home and Scale degrees sit in the key box, Voice leading in the Chords panel's header, and the bottom-row Chords/Notes switch stays in the keyboard dock. Rejected: a "More" overflow menu for Print (built first; dropped once the row had room) and a group of switches in the row (Matthew: nothing else in the toolbar).
- **Play's scope is a two-way segmented toggle, "From the top" or "This bar".** With "This bar" chosen, the button reads "Play bar 4", the name the tutor uses. Rejected: keeping "Play from bar N" as a third option. Matthew asked for one bar versus from the top, and a third option brings back the crowding.
- **Scale degrees goes with the key, not the chords.** The degrees count from home. Matthew's list left it out, so this one is my call. Rejected: dropping the switch.
- **Choices are segmented radios; on/off settings are `role="switch"` buttons drawn as switches.** Each kind keeps one look everywhere. Rejected: pill buttons with a filled dot, which looked like the choices.
- **One tooltip pattern (`src/toolbar/Tip.svelte`) for every option.** It shows on hover and on keyboard focus, `aria-describedby` points at it, and Escape hides it. Each option's one-sentence gloss lives in `content/explainers.json` under `options`. Rejected: native `title` attributes, which keyboard users never see. Also rejected: the separate (?) bubble for voice leading.
- **Drone's blocked reason moved into its tooltip.** It no longer shows as inline text, which kept the row on one line. The reason still leads the accessible description.
- **All key handling is in the key box.** "Play it in another key" (transpose) is a disclosure under the result. "Choose a different home" (re-key) is the existing Bright/Dark and home-note chips, with one line saying the notes stay put and only home moves. The toolbar's re-key dropdown is gone because the chips do the same job. Rejected: a heading above the chips once a key is chosen, which made the chips jump under the cursor between clicks.
- **The `toolbar` element id is kept, now on the transpose disclosure,** so the "Same tune, any key" tip still has an anchor.
- **One pure function, `src/steps/nextStep.js`, drives the step path (Key, then Rhythm, then Chords).** The current step expands, and done steps show a one-line summary. The key's summary has a "Change the key" button that reopens it. "Hide this card" became "Done: on to chords". Rejected: conditionals spread across Landing and App.
- **Rhythm asks only when the meter is provisional,** as a recorded tune's will be. The step shows the guessed meter and tempo with a "Sounds right" button that confirms the meter. Demo tunes show "4/4, set from the tune". The 3-vs-4 question stays parked. Free play's default meter is also provisional, so it gets the same check.
- **Control names live in `content/controls.json`.** The buttons read their labels from it. `server/hearhear/prompt.py` fills `{control:key}` tokens from it at import, and a test checks that every control the prompt names exists there. The Docker image copies the file. The one prompt change beyond the interpolation: the clause about "Play from bar N" is gone, because that control no longer exists.
- **The masthead scroll gap is left to the fixes stream,** as the coordinator directed.
- **Selected and pressed colors live in the components.** Segmented choices, switches, home chips, and transpose keys use `var(--accent)`. The drone switch takes `--sound` through a `sound` prop on Switch. The color pass's role-based rules in `global.css` are deleted. An e2e checks that the chosen label style and the pressed home chip compute to the accent color. Rejected: keeping the id selectors, which keyed on markup this stream changed.
- **The chord row plays nothing while the key is hidden.** `chordRowAction` returns `"none"`, and the dock says "Chords follow the key you choose. Find home first." A tentative key plays chords "in your guessed key". The confirmed text is one sentence that names "the F key", never a bare "F". The piano keys themselves stay playable as single notes, so they are not `aria-disabled`; the A to J row's labels are already hidden before the guess. Rejected: playing the placeholder C's chords, which teaches the wrong home.
