# Stream E2: tutor passphrase gate and follow-ups

Format: **date — decision.** Why. _Rejected:_ alternatives.

The spec is DECISIONS.md's "The live tutor requires a passphrase" and "Before live mode" entries.

## Passphrase gate

- **2026-10-07 — The gate lives in `server/hearhear/access.py`: `normalize`, `code_matches`, and an in-memory `AccessLockout`.** `normalize` casefolds and keeps only `str.isalnum()` characters, then encodes to UTF-8, because `hmac.compare_digest` raises on non-ASCII `str` and a passphrase might not be ASCII. _Rejected:_ comparing `str` directly (a non-ASCII header would crash the request); ASCII-only normalization (it would silently drop letters from a non-English passphrase).
- **2026-10-07 — Settings keep only the normalized code, as bytes, with `repr=False`.** The raw value is never stored, and printing the settings (a traceback, a debugger) can't show it. _Rejected:_ reading the environment on every request (no single place to check that live mode has a code).
- **2026-10-07 — Live mode refuses to start when `TUTOR_ACCESS_CODE` is unset, empty, or has no letters or digits.** A code like `---` normalizes to nothing, which would gate nothing. The error names the variable, never a value, and is raised from `load_settings`, so it fails before uvicorn serves anything, like the existing `ANTHROPIC_API_KEY` check. _Rejected:_ starting and returning 401 to everyone (a misconfigured deploy looks healthy).
- **2026-10-07 — Order of checks in live mode: body cap, validation, rate limit, access lockout, access code, budget.** The gate runs before the budget so an outsider can't learn whether today's budget is spent, and before any Claude call. It runs after the tutor's rate limit because slowapi is a route decorator; wrong guesses therefore also count toward `rate_limited`, which only tightens things. _Rejected:_ a middleware ahead of validation (it would need its own body-free path and duplicate the IP logic; validation is cheap and never reaches Claude).
- **2026-10-07 — Lockout: 5 wrong codes per IP in a sliding 10-minute window, then `429 access_locked` with `Retry-After`.** The forgiving comparison shrinks the search space, so this is much tighter than the tutor limit. Constants, not environment variables: the brief allows one new `.env.example` line, and no one needs to tune it. It keys on the same rightmost `X-Forwarded-For` entry as the rate limit (`client_ip`). Expired entries are swept on each wrong guess, so the table holds only IPs that guessed wrong in the last 10 minutes. _Rejected:_ slowapi's limiter or the `limits` package directly (it is only a transitive dependency, and slowapi counts every request, not just wrong ones); a fixed window (lets 10 guesses straddle a boundary).
- **2026-10-07 — A locked-out IP is refused even with the right code.** Otherwise the lockout response would itself confirm a correct guess, and the limit would protect nothing. A real listener who typos five times waits at most 10 minutes; the recorded lessons stay open meanwhile.
- **2026-10-07 — A missing code, or one with no letters or digits, is a 401 but not a guess.** The panel's first request may go out before it has a code, and a blank field shouldn't lock anyone out. Missing and wrong get different messages ("for invited listeners" vs "didn't match"), both with the same `access_required` code. _Rejected:_ counting every 401 (a client that retries without a code would lock itself out).
- **2026-10-07 — A correct code does not clear earlier wrong guesses.** Simpler, and harmless: a listener with the code rarely guesses wrong. _Rejected:_ resetting on success (one more rule to test, no real gain).
- **2026-10-07 — The 401 and `access_locked` 429 carry `X-Request-Id`; the rejection is logged with the code (`access_required` or `access_locked`), a reason (`missing` or `wrong`), and the request id, never either string.** A test attaches a handler to the `hearhear` logger and checks neither code, raw or normalized, appears in logs, response bodies, response headers, or the settings repr.
- **2026-10-07 — Fixture mode skips the gate entirely and ignores `X-Tutor-Access`.** CI, local development, and the recorded demo need no code (DECISIONS.md).

## Follow-ups

- **2026-10-07 — The `suggestions` event carries `fallback: boolean` beside `served_by`; the eval harness excludes on the flag.** `fallback` is the same value live.py already logs (true when a fallback block or a `fallback_message` iteration appears), and always false in fixture mode. **Amends D15 and `tutor-sse.md`,** which said the harness counts only replies whose `served_by` equals `TUTOR_MODEL`: if the API reports the requested model under another id (a dated snapshot or an alias), a string comparison would exclude good replies. `served_by` stays for reporting. _Rejected:_ dropping `served_by` (the eval report still wants to say which model served a fallback).
- **2026-10-07 — The system prompt states the exact letter-name format:** root A–G, optional `#` or `b`, then one of `""`, `m`, `7`, `maj7`, `m7`, `dim`, `dim7`, `m7b5`, `aug`, `sus2`, `sus4`, `6`, `m6`, with examples and a list of spellings to avoid. The test reads the chord-type enum from `contracts/song.schema.json` (with `M` written as no suffix), so a new chord type fails the test until the prompt names it. The `Suggestion.letter` field description is unchanged, since it generates `contracts/tutor-reply.schema.json`, which this stream doesn't own. _Rejected:_ a pattern on `letter` in the Pydantic model (a contract change, and the client's parser already forgives spellings).
- **2026-10-07 — The Dockerfile comment now says the proxy-header flags affect only uvicorn's access log and `request.client`,** and the limits use `request.client` only when `X-Forwarded-For` is absent. The old wording implied the flags fed the limiter.

## Test changes

- **2026-10-07 — `import_app` moved from `test_app.py` to `helpers.py`** so the access tests can import it without importing another test module. Existing live-mode tests now set a test passphrase (`helpers.ACCESS_CODE`, made up) and send it as a default header; the startup tests set one so they keep testing the API key check.
