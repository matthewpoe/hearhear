# Stream H: evals v1 and the trust panel

Format: **date — decision.** Why. _Rejected:_ alternatives.

- **2026-10-07 — Reference chords are read by code from four-voice hymnal settings, not transcribed by hand.** The sources are Open Hymnal Project ABC files (marked public domain, each naming the printed hymnal it follows: Excell 1900/1915, _The Methodist Hymnal_ 1905, _Common Service Book_ 1917, _Carols Old and Carols New_ 1918). `evals/dataset/derive.js` parses all four voices and names the chord they sound at each change point; the source files are committed and a test fails if the songs drift from them. This makes "never from memory" checkable. _Rejected:_ reading chords off scanned PDFs by eye (unverifiable, error-prone); hymnary.org pages as the citation (its tune pages refused automated fetches, so they couldn't be checked).
- **2026-10-07 — Four tunes: Amazing Grace (3/4), Joyful Joyful (the demo melody, easy case), Veni Emmanuel (E minor with G major pulls: relative-key ambiguity), God Rest Ye Merry (minor with a raised leading tone).** Matches the brief's 3–5 with a minor case and a 3/4 case. _Rejected:_ What Child Is This, whose Open Hymnal transcription came from a 1982 hymnal (not clearly public domain). Blue notes have no tune: no citable harmonization was found, and none is written from memory.
- **2026-10-07 — A change point is a beat where the melody starts a note and the four voices spell a chord different from the previous change point's.** Hymnals harmonize on nearly every beat, so downbeats alone found one chord in all four bars of Joyful Joyful. Beats with a passing or suspended tone, or only two pitch classes, are skipped rather than guessed. The result is dense (41 points), which favors the hymnal's rhythm over a slower, equally good one; the dataset README says so.
- **2026-10-07 — Each request asks about one change point, with no chords in the snapshot.** Hit rate means "the reference is among the suggestions at that point", and a reply holds at most 8 suggestions, so one request per tune would cover only a few points. The melody-only snapshot keeps every point equally hard. _Rejected:_ one request per tune (structurally low hit rate); the reference chords elsewhere in the snapshot (leaks the answer's neighbors).
- **2026-10-07 — A hit is the same root and triad quality.** V7 for a reference V, or C for C6, is the same harmony to the ear; a hymnal's added sixth or seventh shouldn't count as a miss. Only suggestions whose numeral and letter agree count.
- **2026-10-07 — Numeral/letter agreement is by chord identity, per Matthew's "validated by chord identity" decision.** Root pitch class and interval pattern via tonal, with "ø" read as m7b5. The app's `src/tutor/validate.js` still compares strings on this base; Stream F's follow-up changes it. The eval doesn't wait on that.
- **2026-10-07 — Clash rate checks the melody note each suggestion sits on.** The onset note is what the ear hears against the chord; checking every note in the chord's span would need a span the tutor never states.
- **2026-10-07 — The nudge rule errs toward passing prose.** A bare "I" is the pronoun, a bare letter a melody note ("the long E"), a bare digit a degree or bar. Anything with a chord suffix, any other Roman numeral, or "G chord" fails. A stricter rule would flag the fixture's own good nudge ("hold just the 5 underneath"). A model-graded check (PRD) is not built.
- **2026-10-07 — Exclusion uses `served_by`, not a `fallback` flag.** The brief said "suggestions event has fallback true", but the contract (`tutor-sse.md`) and the server report `served_by`, and say the harness counts only replies whose `served_by` equals `TUTOR_MODEL`. The harness follows the contract. In fixture mode the expected value is `"fixture"`, so fixture replies are scored rather than all excluded.
- **2026-10-07 — The model under test comes from the harness's `TUTOR_MODEL`, default `claude-opus-5-5`.** `/api/health` reports the mode but not the model, so the harness can't read the server's setting.
- **2026-10-07 — Rates are stored as count and total.** "3 of 12" is honest about a 41-point dataset where a percentage alone is not.
- **2026-10-07 — The trust panel shows no numbers for a fixture run.** It says plainly that the run checked the plumbing with recorded stand-in replies. Showing fixture hit rates (0%) beside a gloss would read as a measurement. It imports only the run's summaries through Vite's named JSON exports, so the per-reply records stay out of the bundle.
- **2026-10-07 — The harness formats its outputs with Prettier's API.** The generated JSON and Markdown pass `make check`'s format check without a separate step.
- **2026-10-07 — Committed results are a fixture run.** No API key in this phase; the run file and table are labelled as measuring the plumbing, not the model.
