# Stream E: tutor backend decisions

Format: **date — decision.** Why. _Rejected:_ alternatives.

## Rate limit and client IP

- **2026-10-07 — The rate limit keys on the rightmost `X-Forwarded-For` entry, read by the app itself, with the socket address as a fallback.** Verified against the deployed app: one `curl` to `/api/health` with `X-Forwarded-For: 1.2.3.4` reached uvicorn as the caller's real IP (Railway's HTTP log `srcIp` and uvicorn's access log agreed, and neither showed 1.2.3.4). Railway's edge therefore replaces the client's header with one entry it writes. The Dockerfile runs uvicorn with `--forwarded-allow-ips '*'`, which takes the **leftmost** entry for `request.client`. That is correct today only because Railway overwrites the header. Reading the rightmost entry stays correct if Railway, or a CDN in front of it, ever starts appending. _Rejected:_ slowapi's `get_remote_address` (reads `request.client`, so it inherits uvicorn's leftmost choice); `X-Real-IP` (Railway documents it, but I could not verify that a client-sent value gets overwritten).
- **2026-10-07 — The limit is `10/minute;100/day` per IP, overridable with `TUTOR_RATE_LIMIT`.** Ten a minute covers a fast back-and-forth, and a hundred a day covers a long session. The env override exists for the eval harness (Stream H) and tests, which need more. _Rejected:_ a hard-coded limit (evals would hit it); exempting localhost (exemptions are easy to get wrong behind a proxy).
- **2026-10-07 — The rate limit counts only requests that pass validation.** slowapi runs as a route decorator, after FastAPI has parsed the body, so the order is 413, 422, 429, 503. Invalid requests cost nothing upstream. _Rejected:_ `SlowAPIMiddleware` (it is a `BaseHTTPMiddleware`, which wraps streaming responses; the Phase 0 review moved security headers to pure ASGI to avoid exactly that).

## Body cap

- **2026-10-07 — A pure ASGI middleware enforces the 128 KB cap on `/api/` requests.** A declared `Content-Length` over the cap is refused unread. A chunked body is counted as it arrives and refused once past the cap, so a request without `Content-Length` can't get around it. A body under the cap is replayed to the app. It sits inside the security-headers middleware, so the 413 carries the CSP too. _Rejected:_ checking `Content-Length` only (chunked bodies bypass it); relying on Railway's edge (it caps headers at 32 KB, not bodies).

## Live mode

- **2026-10-07 — The structured-output schema is `anthropic.transform_schema(TutorReply)`, built from the same Pydantic model that generates `contracts/tutor-reply.schema.json`.** The API rejects or ignores some JSON Schema keywords (`maxLength`, `minimum`, `maximum`, `pattern`, `maxItems`). The SDK's transform moves them into each field's description, so Claude still sees the bounds, and Pydantic enforces them on the full reply. It is the same transform `messages.parse` uses. _Rejected:_ sending the committed contract file as is (it carries keywords the API won't take); a hand-written copy (contracts are never hand-copied).
- **2026-10-07 — The partial parse uses `from_json(..., allow_partial="trailing-strings")`, not `allow_partial=True`.** With `True`, an unfinished string is dropped, so the message would arrive only when Claude closes the whole field, in one piece at the end. `trailing-strings` includes the unfinished string, so the message streams as it is written. Split escapes (`\"`, `\n`, `é`) are held back until they are complete; tests feed fixture replies one character at a time. Deviation from the brief's wording, not its intent.
- **2026-10-07 — Suggestions are validated one by one; invalid ones are dropped and counted, and so is any suggestion past eight.** One bad suggestion never sinks the reply. A reply whose JSON is incomplete, or whose message or hint level fails validation, ends the stream with `error: invalid_output`, and the message text already shown stays, per `tutor-sse.md`. A `stop_reason` other than `end_turn` (`max_tokens`, `refusal`) is also `invalid_output`. _Superseded by Matthew's review of PRs 8–11: a refusal, a max_tokens stop, or a context-window stop now ends as `unanswerable` ("The tutor couldn't answer that one. Try asking another way."); `invalid_output` is kept for genuinely malformed replies and unexpected stops._
- **2026-10-07 — `max_tokens` is 8,000 and effort is `medium`, set explicitly.** Opus 5.5 always thinks, and thinking counts against `max_tokens`. A full reply is about 2,500 tokens, so 8,000 leaves room to think and caps one turn at about $0.16 of output. `medium` is the model's default; setting it pins the behavior the evals measure. _Rejected:_ 64,000 (the SDK default for streaming; no tutor turn needs it, and it widens the per-request spend); `low` effort (unmeasured; the evals should decide).
- **2026-10-07 — No server-side refusal fallback.** The Claude API skill suggests `fallbacks: "default"` for Opus 5.5. It needs the beta namespace and can switch models mid-turn, which would make the eval numbers describe two models. A music tutor rarely trips safety classifiers, and a refusal surfaces as `invalid_output` with a retry. Proposed to Matthew rather than built. _Superseded by D15; see Wave-1 fixes._
- **2026-10-07 — The client is `AsyncAnthropic(max_retries=1, timeout=120 s read, 5 s connect)`, built at startup in live mode.** One retry keeps a failing turn under Railway's 5-minute idle cutoff. _Corrected in Wave-1 fixes:_ building the client does not prove a key exists (`AsyncAnthropic()` builds without one and fails on the first request), so live mode now checks `ANTHROPIC_API_KEY` at startup.

## Budget

- **2026-10-07 — Usage is read from the stream events (`message_start`, `message_delta`) and charged in a `finally`.** A failed stream or a client that disconnects still charges the input tokens and whatever output was reported. Cache reads and writes count as input. `get_final_message()` would only report usage after a clean finish. _Rejected:_ charging only on success (a client could disconnect early to avoid the budget).
- **2026-10-07 — Over budget means today's spend has reached the limit; the reply that crosses it finishes.** One in-flight reply can overshoot by at most `max_tokens` plus its input. The Console spend limit is the hard cap. _Rejected:_ reserving `max_tokens` up front (more state for little gain at one worker).
- **2026-10-07 — The budget resets at midnight UTC** and on redeploy (it is in memory), as the PRD accepts.

## Prompt and injection posture

- **2026-10-07 — Each request becomes one user message: the snapshot, history, and question as JSON inside `<snapshot>`, `<history>`, and `<student_message>`, with `<` and `>` escaped as `<` and `>`.** No field can close its tag, and the student's words still reach Claude exactly. Only validated closed-set values (hint level, label style, key provisional) appear outside the tags. History is folded into the data rather than replayed as assistant turns, so a client-edited "tutor" turn can't speak in the tutor's voice. This also avoids a last-turn assistant message, which Opus 5.5 rejects as prefill. _Rejected:_ mapping history to user and assistant roles (gives forged tutor turns the model's own voice).
- **2026-10-07 — `snapshot.version` is removed from what Claude sees,** per `tutor-sse.md` ("Claude never sees or produces it"); the server echoes it in the `suggestions` event.
- **2026-10-07 — A provisional key is handled in the prompt: don't name the key, tonic, or mode, and return no suggestions.** Letter-name suggestions would give the key away during a demo. Nudge-level replies also return no suggestions, which matches the nudge fixture. For a provisional key this stays prompt-level; the server-side guarantee keys on `key_hidden` (D5, see Wave-1 fixes).
- **2026-10-07 — No prompt caching yet.** The system prompt is about 1,000 tokens, under Opus's minimum cacheable prefix, so a cache breakpoint would do nothing. Revisit if the prompt grows.

## Logging

- **2026-10-07 — One JSON line per event on stdout** (`tutor_live`, `tutor_fixture`, `tutor_invalid_reply`, `request_rejected`): request id, model, hint level, outcome, dropped count, input and output tokens, budget spent, and duration. Never the question, history, snapshot, reply text, client IP, or any key. The request id goes back to the client as `X-Request-Id`. Rejections at 413 and 429 happen before a request id exists and are logged by code only.

## Code layout

- **2026-10-07 — Small modules by concept:** `prompt.py`, `reply_stream.py` (partial parser and validation), `live.py`, `budget.py`, `limits.py`, `log.py`, `errors.py` (the JSON error envelope, shared by 413, 422, 429, and 503). `tutor.py` keeps SSE framing and fixture mode. Tests share `helpers.py` (snapshot, SSE parser) and a `client` fixture in `conftest.py` that resets the limiter and budget.

## Wave-1 fixes

Applies Matthew's triage (DECISIONS.md, "Wave 1 triage": D1, D5, D15) and his calls on the Fable review of this stream.

- **2026-10-07 — D1: the CSP allows abcjs's one `<style>` element by hash: `style-src 'self' 'sha256-BCpnf71gZdCsSCHDzyB1RsBbZ0qQdqseK6v+yJsgg30='`.** The hash is of the exact rule abcjs 6.7.1 builds in `set-paper-size.js` and inserts as the element's `textContent` (`insertStyles` in `svg.js`). `style-src-attr 'unsafe-inline'` stays. Verified in Chromium (Playwright): the built app's server on a spare port served a page rendering abcjs 6.7.1's own bundle; with the header as shipped there was no console error and no `securitypolicyviolation`; with the hash stripped from the header (the control), Chrome blocked the element under `style-src-elem` and named the same hash. Two tests pin it: the header carries the hash of the rule's text, copied into the test with a comment naming 6.7.1, and `package-lock.json` still locks abcjs at 6.7.1, so an upgrade fails a test before it fails silently in the browser. _Rejected:_ `style-src-elem 'unsafe-inline'` (D1).
- **2026-10-07 — D5: the snapshot carries `key_hidden` (default false), and while it is true the server withholds every suggestion.** `toTutorSnapshot(song, { labelStyle, keyHidden })` sends it. The prompt states it outside the data as `Key hidden: yes|no` (removed from the snapshot JSON so it has one source), and the system prompt tells Claude not to name or hint at the key, tonic, mode, or key signature, through letter names, degrees, or numerals included, and to return no suggestions. The server does not rely on that: `suggestions_data` in `tutor.py` sends `suggestions: []` and adds the withheld count to `dropped`, and `tutor_live` logs it as `withheld_hidden`, so the evals can see how often the prompt alone would have leaked. Fixture mode applies the same rule through the same function, so the two modes can't drift. This answers the reviewer's medium finding on `reply_stream.py`, keyed on `key_hidden` rather than `key.provisional` per D5. A provisional key without `key_hidden` (free play on the tentative C) keeps the prompt-level rule only.
- **2026-10-07 — D15: live requests opt into the server-side refusal fallback, and every reply reports `served_by`.** Confirmed against the installed SDK (anthropic 1.11.0) before writing it: `client.beta.messages.stream(..., fallbacks="default", betas=["server-side-fallback-2026-07-01"])`; the `"default"` scalar needs exactly that header (the array form uses `-2026-06-01`, and mixing them is a 400). `served_by` comes from three signals, in stream order: `message_start`'s `message.model` (names the fallback model for a pre-output decline or a sticky-routed conversation), a `fallback` content block's `to.model` (a mid-stream decline), and a `fallback_message` entry in `message_delta`'s `usage.iterations` (the documented served-by signal). With a fallback, top-level usage covers only the serving attempt, so the budget charges the sum of `usage.iterations` when it is present. Fixture replies report `served_by: "fixture"`, which never equals `TUTOR_MODEL`. The log line carries `served_by` and `fallback`. A test drives the real SDK over an `httpx2.MockTransport`, so the wire request (path, beta header, `fallbacks`) and the parsing of a fallback block and `usage.iterations` are checked against the SDK itself, not only a fake.
- **2026-10-07 — Unwrapped errors mid-stream end the stream with `error: upstream` and `done` (review, high).** After the two SDK clauses, a final `except Exception` records `internal_<TypeName>` as the outcome and logs `tutor_stream_failed` with the type name only, never `str(exc)`. `CancelledError` and `GeneratorExit` are not `Exception`s, so a client disconnect still logs as `disconnected`. Tests cover `httpx2.ReadError`, `RemoteProtocolError`, and the SDK's `RuntimeError` for bad event order mid-stream (budget charged for tokens so far), and a failure opening the stream.
- **2026-10-07 — Live mode refuses to start without `ANTHROPIC_API_KEY` (review, medium).** `_api_key()` in `app.py` raises a `RuntimeError` naming the variable, never its value, when it is unset, empty, or blank, and the key is passed to `AsyncAnthropic(api_key=...)` explicitly. I did both of the reviewer's options: the check makes the deploy fail at import, and passing the key explicitly stops the SDK from quietly falling back to another credential source (an auth token or a CLI profile), so what the server checked is what it uses. Tests import the app in a fresh interpreter, as uvicorn does: live with no key, an empty key, or a blank key fails; live with a key starts without echoing it; fixture mode needs none.
- **2026-10-07 — A 429 carries `Retry-After` in whole seconds (review, low).** The handler reads the tripped limit from `request.state.view_rate_limit` (slowapi sets it before raising) and asks the limiter's storage when that window resets. _Different from the reviewer's simpler option:_ not `Limiter(headers_enabled=True)`, which makes slowapi inject rate-limit headers into every limited response and requires each limited endpoint to take or return a `Response`, a poor fit for a `StreamingResponse`. And because the per-day limit can mean hours, the message now depends on the wait: "give the tutor a minute" for up to 60 seconds, otherwise "that's the tutor's limit for now; the recorded lessons still work," so the copy never promises a minute it can't keep.
- **2026-10-07 — Settings overrides in tests use one helper, `settings_with(**overrides)`, a `dataclasses.replace` (review, low).** _Different from the proposal:_ it lives in `helpers.py`, not `conftest.py`. Tests already import shared code from `helpers.py`, and importing from `conftest.py` is an anti-pattern pytest warns against. All three call sites use it.
- **2026-10-07 — `TUTOR_RATE_LIMIT` is in `.env.example` and the README has an Environment section (review, low).** The README table lists `TUTOR_MODE`, `TUTOR_MODEL`, `ANTHROPIC_API_KEY`, `TUTOR_DAILY_TOKEN_BUDGET`, and `TUTOR_RATE_LIMIT`. It says plainly that nothing loads `.env` automatically, which is true today (flagged for Matthew below). The Dockerfile comment no longer claims the proxy-header flags feed slowapi: the limiter reads `X-Forwarded-For` itself, and the flags only give uvicorn's access log and the limiter's no-header fallback the forwarded client address.
- **2026-10-07 — The system prompt tolerates history that doesn't alternate (from Stream F's review).** History is data inside one user turn, so any order is already a valid API request. The prompt now says turns need not alternate: history may open with a tutor turn (the app's greeting), or hold two tutor or two student turns in a row. Tests send all three shapes.
- **2026-10-07 — `contracts/tutor-sse.md` matches the code.** It documents `served_by`, the hidden-key rule, `allow_partial="trailing-strings"`, the `X-Request-Id` header, that the 503 `over_budget` arrives as JSON before any stream (checks run in the order body cap, validation, rate limit, budget), `Retry-After` on the 429, and that staleness uses the song version the client captured at send time (equal to `snapshot_version` by construction, per Stream F's decision log).

**For Matthew (not done here):** nothing loads `.env` (the Makefile's `dev` target and the server read only the process environment), so `.env.example`'s "copy to .env" line promises more than it does; Stream F's panel must pass `keyHidden: keyLabelMode(song, ui) === "hidden"` to `toTutorSnapshot` for D5 to take effect in the app; and Stream H's harness must compare `served_by` to `TUTOR_MODEL` per D15. Untested against the live API: how a mid-stream fallback continues a structured-output JSON reply. The docs say the fallback model continues from the partial text, which the parser handles (tested with a fake and with the real SDK over a mock transport); if it restarted the JSON instead, the turn would end as `invalid_output` and the log would show `fallback: true`, so the first live evals will tell.
