# Stream D3: key finding and demo loading (wave 1)

Format: **date — decision.** Why. _Rejected:_ alternatives.

- **2026-10-07 — The key prompt lives inside the Welcome region.** `App.svelte` mounts only `Landing.svelte` for this stream, and D3 can't edit it, so Landing switches between the song chooser, the key prompt, and the guess result. The region keeps its "Welcome" label for the smoke test. _Rejected:_ a separate region (needs an `App.svelte` change; requested in contractRequests instead if Matthew wants one).
- **2026-10-07 — "Major, minor, or a specific key" is one control: a mode choice plus twelve homes, starting on the current hypothesis.** With C major preselected, "yes, 1 is home and it's major (or minor)" is one click, and any other key is two. Modes carry a plain gloss ("bright", "dark") for non-musicians. Tonics use conventional spellings per mode (Db major, C# minor). _Rejected:_ separate Major and Minor buttons that commit without a tonic (ambiguous: they'd silently mean C); a 24-item select (slow, not glanceable).
- **2026-10-07 — Help shows rankKeys' top three in rank order, with no scores and no "best" label,** each with "Hold X underneath" and "Make X home". Out-of-scale notes are an annotation ("Outside D major: F natural"), per the PRD. _Rejected:_ showing correlation scores (reads as a verdict); shuffling the order (hides a real signal and confuses repeat visits).
- **2026-10-07 — The drone test plays the whole melody with chords left out** (`playPhrase(..., { chords: [] })`) over the candidate tonic, voiced in the highest octave below the melody's lowest note. Without chords the drone is the only harmony, so settle-or-itch is a clean comparison. Each melody note lights on the keyboard as it sounds (`ui.keyboardLights.melody`), the drone in `keyboardLights.chord`. _Rejected:_ a fixed drone octave (collides with low melodies, the same problem as the voicing steer).
- **2026-10-07 — The drone glows as "other" (neutral) while labels are hidden, and as "tonic" otherwise.** Hidden mode forbids function colors before the guess; after it, the drone asks "what if this were home?", so tonic blue fits. _Rejected:_ always tonic (colors before the guess); a melody-highlight channel for the drone (it isn't melody).
- **2026-10-07 — Committing a guess calls `song.rekey({ tonic, mode, provisional: false })` and clears `ui.demoAwaitingGuess`,** and stops any listening test so the reveal isn't under a stale drone. "Try another home" reopens the prompt on the current guess; it re-keys again.
- **2026-10-07 — After a guess, both outcomes get the same shape; only the next step differs.** "Home is G major. The colors follow your guess." A guess that doesn't match the demo's true key (compared by pitch class and mode, so enharmonics count) gets "Want to check it by ear? Hold this note underneath. Does the melody settle or itch?" A matching guess, or any free-play guess, gets "Next, click a note on the staff and try a chord under it." No buzzer, no "wrong", no correction. _Rejected:_ telling the user they're right or wrong (a verdict).
- **2026-10-07 — In free play the prompt appears after 8 notes on the provisional C ("a phrase or so"), without stealing focus, and has "Not now".** A demo's prompt takes focus (the user just asked for it by loading a tune) and has no "Not now", since the demo waits for a guess. _Rejected:_ no free-play prompt in wave 1 (the PRD makes key finding first-class for free play too).
- **2026-10-07 — Loading a demo stops audio, loads the tune on provisional C, clears selection, playhead, and keyboard lights, sets `demoAwaitingGuess`, then unlocks audio on that click.** The tune's own meter is kept; meter finding is wave 2. Blurbs on the song cards say nothing about key or mode ("a slow New Orleans lament", not "minor-key dirge").
- **2026-10-07 — Audio boundaries are visible.** Landing preloads samples on mount and shows "Warming up the piano…", a failed message with retry (`preload()`), and a "sound blocked" message with retry (`unlock()`). Each listening test shows Stop while playing and "Try again" with an alert on failure.

## Known gaps

- Undoing a guess returns the song to provisional with `demoAwaitingGuess` already false, so labels show as tentative rather than hidden, and the prompt reappears as the free-play prompt.
- After a transpose, a demo's guess is compared to the untransposed true key, so a correct guess would get the "check it by ear" step. Transpose isn't in wave 1.
- C major and C minor in the help list share a "Hold C underneath" button name; the drone is the same note, so the action is identical.

## Wave-1 fixes (Oct 7, 2026)

Rebased onto `merge/a-theory` (contracts v2 and the theory core); the rebase was clean.

- **Listening tests play through `playWithVisuals` (D10; covers the playhead finding).** `listen.js` no longer calls `playPhrase` or writes `ui.keyboardLights`. "Hear the tune" and every drone test call `playWithVisuals({ fromTick: 0, toTick: end }, { chords: [], drone })`, so the staff playhead and the keyboard follow the sound. `stopListening()` is the audio `stop()`; the driver clears what it lit.
- **The drone is released by the driver's own cleanup (low finding: drone outside `try`).** With D10 the drone is held and released inside `playWithVisuals`, so D3 no longer starts it outside a `try` or lights a key itself. Note for Stream C: the current stub calls `holdDrone(drone)` just before its `try`; the real implementation should hold it inside, so a synchronous audio failure still runs the cleanup.
- **ListenButton is one button (fix as proposed).** Its label, icon, and handler follow `status`, so keyboard focus stays on it when playback starts and ends. A run counter keeps a stale play from overwriting the status after Stop. _Different from the proposal:_ no `aria-pressed`. A toggle whose label also changes ("Hear the tune" to "Stop") reads as "Stop, pressed" in screen readers; the changing label says it alone.
- **`droneMidi` floors at C2 (fix as proposed, refined).** Instead of `Math.max(midi, 36)`, which would put the drone on C whatever the key, it raises the drone by octaves until it reaches C2 (`LOWEST_MIDI`), so it stays on the key's tonic and shares the melody's register when the melody reaches that low. The audio contract states the C2 bound only in prose, so `keys.js` names it as a constant.
- **`sameHome` compares pitch classes (fix as proposed).** It no longer depends on the register `degreeToMidi` picks.
- **Tests (D6).** `tests/finding/keys.test.js`: the drone sits within an octave below the lowest note of both demo tunes (true key and provisional C), the C2 floor, C#/Db and F#/Gb equality, and `easyModeHomes`.
- **Easy mode (DECISIONS.md, "Help me find it is an easy mode").** The prompt still asks its direct question first. "Not sure, help me find it" opens `KeyCandidates.svelte`, rebuilt as easy mode: the `keyFinding` explainer from content/explainers.json, verbatim; then drone 1 (the current home, the provisional C in a fresh demo) and drone 2 (the top-ranked candidate that differs from it, picked by the new pure helper `easyModeHomes`). Drones are unnamed ("Drone 2 feels like home"), so only the choice, which commits the guess, names the key and reveals the colors. "Neither feels like home? Try more drones" offers the other two top candidates the same way. The out-of-scale annotations are gone, since they name notes before the choice. The homes are fixed when easy mode opens, so they don't reshuffle under the user.
- **Same next step after any guess (D14).** GuessResult always offers "Check it by ear" with the drone, plus "Try another home"; it no longer compares the guess with the true key. `trueKeyOf` had no other caller and was removed.
- **Demo flag (D18).** A guess no longer clears `ui.demoAwaitingGuess`, so undoing it brings back the hidden labels and the prompt. `loadDemo` sets it. D3 has no path that leaves a demo (it only loads demos), and nothing outside D3 clears the flag yet; whoever replaces the song with a non-demo one (clearing it, importing ABC) must clear it. That is deferred to Matthew's list.
- **Warm-up (D19).** The landing calls `preload()` in `onMount` and `unlock()` (which plays the sound-check chord) on the first click anywhere on the page, through a one-shot capture listener, so the first click of any kind starts sound. A blocked unlock still shows "Turn sound on".
- **Explicit view state (fix as proposed).** The landing's four booleans and three-closure `dismiss` are replaced by one `intent` state (`ask`, `dismissed`, `reopened`, `guessed`) and a derived `view` (`none`, `prompt`, `find`, `result`) that also reads the provisional key and the demo flag. The warm-up is an `onMount`. The event-filter nit in `listen.js` went away with D10.
- **Free-play prompt kept, with "Find the key" (Matthew's call).** After "Not now" in free play, a "Find the key" button stays while the key is provisional and reopens the prompt.
- `loadDemo` clears `keyboardLights` in the v2 shape (`source: null`).
- The two bullets above about transposes and shared "Hold C underneath" names no longer apply: GuessResult doesn't compare with the true key, and easy-mode drones are numbered.
