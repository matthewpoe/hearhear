# Stream D2: chord dropdown and chip row

Format: **date — decision.** Why. _Rejected:_ alternatives.

- **2026-10-07 — `ChordDropdown.svelte` stays the region root** (`id="chords"`, labeled "Chords") and holds both the chip row (`ChordChipRow.svelte`) and the dropdown. `App.svelte` imports only this component, and the dropdown has to be opened from both the staff (`onNoteClick`) and the chips, so the open state lives in one place. _Rejected:_ a separate popover component that the chip row and region each talk to (a second channel for "open at this note").
- **2026-10-07 — Pure helpers sit beside the components:** `options.js` (candidates ordered by `fit`, the "why" label from `analyzeNoteOverChord`, number key to degree), `passage.js` (the bar around a note and the voicing inputs), and `chordView.js` (label in the user's style, function, shape, accessible name, by key-label mode). They compose theory functions and compute no theory of their own. _Rejected:_ computing these inline in the components (the PRD forbids theory in components).
- **2026-10-07 — The audition range is the bar the note starts in, stretched to the note's end** when it is held across the bar line. Bar 0 is the pickup (0 to `pickupTicks`). Comes from `rebar`, so it follows the current meter hypothesis.
- **2026-10-07 — Every candidate for a note shares one voicing context:** `below` is the lowest melody note starting in that bar (theory's `passageBelow`, since Wave-1 fixes), and `previous` is the voicing of the nearest chord placed before the note (voiced with no previous of its own). A and B therefore differ only in harmony, as the PRD's audition rule requires. _Rejected:_ chaining voice leading back through every earlier chord (slower, and the audio stream voices the other chords itself).
- **2026-10-07 — No pre-selection; ties keep the theory core's order.** Options sort by `fit` descending with a stable sort, and opening the dropdown focuses the dialog, not an option, so no chord sounds or lights until the user moves.
- **2026-10-07 — Number keys focus the option for that degree** (1–7, no modifiers, read from `KeyboardEvent.code`), and focus auditions it, so the next Enter commits what was just heard. Pressing the same number again re-auditions. Only diatonic roots in the likely list answer to a number; degrees with no candidate (vii in major, ii and vii in minor) do nothing. The handler calls `preventDefault`, which the number row honours (see below).
- **2026-10-07 — Arrow Up/Down move between the dropdown's buttons; Tab works too.** Tabbing out, or a pointer press outside, closes the dropdown without restoring focus (the user is going somewhere). Escape closes and returns focus to the opener (the chip, or whatever had focus when the staff note was clicked). Closing without choosing stops an audition this dropdown started; choosing lets it ring.
- **2026-10-07 — Keyboard lights follow the hovered option, else the focused one,** and show the candidate's voicing in its function color plus the melody note as a neutral highlight. In hidden mode the color is `other`, so the keyboard doesn't reveal function. The dropdown clears `ui.keyboardLights` only if it set them, so it never wipes the transport's lights. (Wave-1 fixes: lights now carry `source: "hover"` and yield to playback, per D10.)
- **2026-10-07 — Hidden mode shows letter names only** (superseded by D2 in Wave-1 fixes: a neutral mark only). Letter names are not key-relative; numerals, Nashville numbers, function colors and shapes, and the function name in the accessible label are all withheld. Tentative chips are outlined (dashed edge, unfilled shape at `--tentative-opacity`); confirmed chips are filled with the function's soft color and a solid shape, and the change animates over `--dur-reveal` (zero under reduced motion).
- **2026-10-07 — Chip design: soft function background, solid function shape, `--ink` text.** Text never sits on a saturated fill, so every function, including yellow, keeps AA contrast without a per-function text token, and yellow takes `--fn-subdominant-edge` as its outline per the PRD. _Rejected:_ saturated fills with `-ink` text (the shape would vanish into its own fill).
- **2026-10-07 — Nashville sevenths render as a superscript `7`** (`nashvilleOf` returns a plain 7; the view raises it). `maj7` stays inline, per the PRD's notation list.
- **2026-10-07 — Tutor suggestions show in two places, never applied.** In the chip row, each suggestion is a dashed card with "Hear it" (audition at its note) and "Compare" (opens the dropdown on that note). In the dropdown they form a "From the tutor" group with confidence and reason, and choosing one is the only way it reaches the song. Labels re-derive from the suggested chord and the current key rather than trusting the tutor's numeral, so a re-key relabels them. Stale sets (`isStale`) carry a visible note and a dotted outline. Suggestions whose note no longer exists are counted ("one idea was for a note that's no longer there"), never re-anchored.
- **2026-10-07 — "No chord here" removes a placed chord** (`song.setChord(noteId, null)`). Placing a chord without a way to take it back would leave only undo, and the PRD says the dropdown both places and changes chords.
- **2026-10-07 — "Something else…" is a disclosure button** (`aria-expanded`) that reveals the extended candidates below it, deduplicated against the likely list and ordered by fit. Keeping the button in place keeps focus inside the dropdown. _Rejected:_ replacing the button with the list (focus would fall to the page body and keyboard handling would stop).
- **2026-10-07 — Audio status in the dropdown:** loading shows "Loading piano sounds…"; failed shows an alert with "Try again", which calls `preload()` and reports a rejection in place. The dropdown doesn't call `unlock()`: unlocking plays the sound-check chord, which belongs to the landing screen.
- **2026-10-07 — The dropdown is absolutely positioned in page coordinates** below the anchor rect, clamped inside a 16px gutter, so it scrolls with the staff. Max height 70vh with its own scroll.

## Wave-1 fixes

- **2026-10-07 — Hidden mode shows a neutral mark only (D2).** `chordView` returns empty text, no function, no color, and the accessible name "Chord, name hidden until you find home" in hidden mode; the badge draws a short neutral rule. This applies in the dropdown too, where the "why" label still tells options apart: a letter name there would give home away as readily as on a chip.
- **2026-10-07 — Shapes from the shared `FunctionMark`, colors from `functionInfo` (D3, D8).** `chordView` no longer imports `contracts/functions.json`; it returns `functionInfo(fn).color` (a tokens.css property name), and `ChordBadge` derives `--c`, `-soft`, and `-edge` from it (`-edge` falls back to the base color where no edge token exists). The badge's own SVG shapes are gone. The shape keeps a 1px edge stroke so yellow holds 3:1 on its soft fill.
- **2026-10-07 — Voice-leading toggle and explainer in the dropdown (D4).** A `role="switch"` button bound to `ui.auditionVoicing` ("Voice leading: off/on", default off = `as-song`), passed as `neighbors` to every audition. Beside it, a "What's voice leading?" disclosure button (`aria-expanded`, `aria-controls`) renders `content/explainers.json`'s `voiceLeading` title, body, off, and on text verbatim. Both are buttons, so Arrow Up/Down reach them. After a chord is chosen (not after "No chord here"), the dropdown silences its audition and replays the bar once through `playWithVisuals(range)`, which voices the song's chords naturally.
- **2026-10-07 — Shared channels (D10).** Closing without choosing calls `stopAudition()`, never `stop()`. `below` is `passageBelow(song, range)`: notes that start in the range, B's rule, so a candidate sits in the register of the chords B voices around it. Keyboard lights carry `source: "hover"`, are written only while the source isn't `"playback"`, and are cleared only while it is still `"hover"`. The effect tracks the lights' source, so when playback ends and releases the keyboard, a still-focused option re-lights (the stale-`lit` finding); it skips the write when the store still holds exactly what it last wrote for the same option and passage, so its own write never loops.
- **2026-10-07 — Label mode read untracked in the lights effect** (reviewer's fix). The effect reads `ui` and `song` inside `untrack`, so it no longer relies on `$derived`'s equality check to avoid an update loop, and the comment says so.
- **2026-10-07 — Focus returns to SVG staff notes** (reviewer's fix): the opener is any focused `Element` other than `<body>`, focused back as `HTMLElement | SVGElement`.
- **2026-10-07 — "Hear it" sounds at once** (reviewer's fix): the chip row's click calls `auditionChord` directly; hover and focus keep `auditionDebounced`. Rejections are ignored there because audio failures already surface through `audioStatus`.
- **2026-10-07 — No recomputed passage on hover** (reviewer's fix): `preview` auditions with the dropdown's derived `passage`; only "Hear it" (another note) calls `passageAround`. The bar/beat label is one helper, `whereOf(note, meter)` in `chordView.js`, used by both components.
- **2026-10-07 — The dropdown stays clear of the keyboard dock** (reviewer's fix, extended). After opening, it measures itself and the sticky `.keyboard-dock`: below the anchor if it fits, else flipped above it, else on the roomier side with `max-height` capped to that space. The reviewer proposed clamping `top`; flipping first keeps the anchor visible, which a clamp would cover.
- **2026-10-07 — Unit tests (D6):** `tests/chords/passage.test.js` (pickup range, whole bar, range held across a bar line, `below` from onsets, previous-chord voicing, `whereOf`) and `tests/chords/options.test.js` (fit ordering with ties in `candidates()` order, asserting the fixture has a tie; "why" labels; extended dedupe; `degreeOf`; `chordView` in hidden, tentative, and confirmed for every label style, Nashville superscript seventh and inline maj7).
- **2026-10-07 — The number row needs no shared flag** (reviewer's fix): the contract request is withdrawn above, and the Digit handler drops `stopPropagation`, keeping `preventDefault`.

## Review fixes: touch and positioning

- **2026-10-07 — On touch, the first tap on an option previews it and a second tap on the same option chooses it.** A finger can't hover, and a tap fires focus and click together, so a single tap used to commit a chord the student never heard. Now a tap auditions the option, lights its tones, and keeps its "why" label in view; the option is outlined with "Tap again to choose", and a `role="status"` region announces "{chord}. Tap again to choose." Tapping a different option previews that one instead. Mouse (hover auditions, click chooses) and keyboard (focus auditions, Enter chooses) are unchanged. The decision lives in `tap.js` (`activate`, `pointerTypeOf`): Enter and Space synthesize a click with `detail` 0 and read as keyboard even after a tap; otherwise the click's own `pointerType` wins where the browser sets one, else the type from the option's last `pointerdown` (WebKit's click is not always a `PointerEvent`). Options set `touch-action: manipulation` so a quick second tap isn't taken as double-tap zoom. Tests: `tests/chords/tap.test.js`. _Rejected:_ a long-press to choose (undiscoverable), and suppressing the compatibility `focus` (it would leave keyboard users on hybrid devices without auditions).
- **2026-10-07 — Positioning: no ancestor is a containing block, so the dropdown stays in place with a guard, not a portal.** Checked in source (`App.svelte`, `global.css`, `index.html`) and in the built app in Chromium at 1280×800 and 390×844: `section#chords`, `main.workspace`, `div#app`, `body`, and `html` all compute `position: static` with no `transform`, `filter`, `backdrop-filter`, `perspective`, `contain`, `will-change`, `container-type`, or `content-visibility` that would create one. (The sticky `.keyboard-dock` is a sibling, not an ancestor; the dropdown's own entry animation transforms only itself.) On every open, `containingAncestor` (`containingBlock.js`) walks the dropdown's ancestors and logs a console error naming the first containing block and the style that makes it one, which the e2e smoke test counts as a failure. Verified by setting `main { position: relative }` in the browser: the error fires. Tests: `tests/chords/containingBlock.test.js`. _Rejected:_ portalling to `<body>` pre-emptively (moves the dialog out of the "Chords" region and needs its own focus-out and click-outside plumbing, for a problem that doesn't exist today).
